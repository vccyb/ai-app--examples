# 01 - 规格定义阶段 (Specification)

## 阶段目标

明确芯片的功能需求、性能指标、接口定义和设计约束，为后续设计提供依据。

## 输入

| 输入项 | 说明 | 来源 |
|--------|------|------|
| 市场需求 | 产品功能需求 | 产品经理/客户 |
| 竞品分析 | 参考现有芯片 | 市场调研 |
| IP文档 | 可复用的IP核 | IP供应商 |
| 工艺库 | 目标工艺参数 | 晶圆厂 |

## 关键输出件

| 输出文件 | 内容 | 模板位置 |
|----------|------|----------|
| **规格书** | 完整功能规格说明 | `spec_template.md` |
| **接口定义** | 引脚定义、时序图 | `interface_spec.xlsx` |
| **架构文档** | 总体架构、模块划分 | `architecture.md` |
| **验证计划** | 验证策略、测试点 | `verification_plan.md` |

## 核心指标

| 指标类别 | 关键指标 | 说明 |
|----------|----------|------|
| **性能** | 时钟频率 | 如: 1GHz |
|  | 吞吐量 | 如: 1000 Mops |
|  | 延迟 | 如: <10ns |
| **面积** | 门数 | 如: 500K gates |
|  | 芯片面积 | 如: 2mm² |
| **功耗** | 动态功耗 | 如: 100mW @ 1GHz |
|  | 静态功耗 | 如: 10mW |
| **接口** | I/O数量 | 如: 100 pins |
|  | 支持协议 | 如: SPI, I2C, UART |

## 设计检查清单

- [ ] 功能需求是否完整
- [ ] 性能指标是否可测试
- [ ] 接口定义是否明确
- [ ] 功耗预算是否合理
- [ ] 验证计划是否覆盖所有功能

## 示例项目规格

本项目以 **简易UART控制器** 为例:

```
功能: 支持标准UART通信，可配置波特率
时钟: 50MHz
波特率: 9600, 115200 可选
FIFO: 发送/接收各16字节
接口: APB总线 + UART TX/RX
面积目标: <10K gates
功耗目标: <5mW @ 50MHz
```

---

`★ Insight ─────────────────────────────────────`
1. **规格冻结至关重要**: 规格变更在设计后期代价巨大，通常有ECO (Engineering Change Order) 流程管理变更
2. **可测性设计**: 规格阶段就应考虑DFT (Design for Test)，如扫描链、JTAG等
3. **接口标准化**: 尽量使用标准接口协议 (AMBA, AXI, APB) 便于SoC集成
`─────────────────────────────────────────────────`
