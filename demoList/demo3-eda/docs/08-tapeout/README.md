# 08 - 流片阶段 (Tapeout)

## 阶段目标

将最终验证通过的版图数据 (GDSII) 交付给晶圆厂，启动芯片制造流程。这是设计流程的最后一步。

## 输入

| 输入项 | 来源 | 说明 |
|--------|------|------|
| GDSII | 物理验证 | 最终版图 |
| 网表 | 后端设计 | 用于测试 |
| 测试向量 | 验证阶段 | 用于ATE测试 |
| **签收报告** | 各阶段 | 时序/DRC/LVS等 |

## 关键输出件

| 输出文件 | 说明 | 接收方 |
|----------|------|--------|
| **GDSII流片文件** | 最终版图数据 | 晶圆厂 |
| **测试向量** | ATE测试数据 | 封测厂 |
| **文档包** | 设计说明、引脚定义等 | 客户/生产 |

### GDSII文件格式

GDSII (Graphic Design System II) 是二进制流格式，包含:

| 数据类型 | 说明 |
|----------|------|
| **结构 (GDSII Structures)** | 层次化设计单元 |
| **图形 (GDSII Elements)** | 多边形、路径、文本 |
| **层 (Layers)** | 不同工艺层 (M1, M2, VIA1...) |
| **单元 (Cells)** | 可复用设计模块 |

## 测试向量生成

### ATE (Automatic Test Equipment) 测试

```verilog
// 生成测试向量
module uart_test_vectors;
    // 测试模式
    task test_uart_tx();
        // 刺激
        force top.uart_tx.tx_start = 1;
        force top.uart_tx.tx_data = 8'hA5;
        #1000;
        // 预期输出
        expect top.uart_tx == 1;
    endtask

    // 生成ATE格式
    initial begin
        $display("V1");  // 向量版本
        $display("PIN tx_clk tx rst_n data_in expected_out");
        // 测试向量行
        $display("0 1 0 1 00000000 Z");
        $display("10 1 0 1 10101010 0");
        // ...
    end
endmodule
```

## 流片会议 (Tapeout Review)

### 会议议程

1. **设计总结**
   - 芯片功能
   - 关键规格
   - 创新点

2. **验证状态**
   - 覆盖率报告
   - 已知问题 (如果有)
   - 风险评估

3. **物理设计**
   - 面积/功耗/性能总结
   - 时序余量分析
   - 可靠性评估

4. **生产准备**
   - 封装方案

## 制造流程概述

### 从GDS到晶圆

```
GDSII → 数据准备 → 掩模制作 → 晶圆制造 → 封装 → 测试 → 交付

↓       ↓           ↓           ↓         ↓       ↓       ↓
数据    FRAM        光刻工艺    硅工艺    引线    ATE    芯片
转换    切割        电子束      注入      键合    测试
        裸片        光刻胶      离子      塑封
```

### 时间线

| 阶段 | 时间 | 说明 |
|------|------|------|
| **数据准备** | 1-2周 | GDS处理、DFM |
| **掩模制作** | 2-4周 | 电子束曝光 |
| **晶圆制造** | 4-8周 | 光刻→刻蚀→离子注入... |
| **封装** | 1-2周 | 划片、键合、塑封 |
| **测试** | 1-2周 | ATE测试、分类 |
| **总计** | **2-4个月** | 从流片到样片 |

## 风险管理

### 流片风险

| 风险类型 | 概率 | 影响 | 缓解措施 |
|----------|------|------|----------|
| **功能Bug** | 中 | 高 | 完善验证、形式验证 |
| **时序违例** | 低 | 高 | 多Corner签收、加余量 |
| **良率低** | 中 | 中 | DFM优化、测试向量完善 |
| **封装问题** | 低 | 中 | 早期封装样品测试 |
| **市场变化** | 高 | 高 | 灵活供应链、小批量 |

### 应急预案

```
如果样片测试发现问题:

1. 功能Bug → Metal Fix (金属层修改)
   - 只能修改M1-Mx, 不能修改晶体管
   - 成本: $50K-200K
   - 时间: 2-4周

2. 时序问题 → 降压使用
   - 降低工作频率
   - 软件 workaround

3. 无法修复 → 重新流片
   - 修改RTL
   - 完整流程重新走一遍
   - 时间: 6-9个月
```

## 经验教训

### 常见流片失败原因

1. **验证不足** - 覆盖率不够，边界case未测试
2. **时序乐观** - 只看TT角, SS/FF未收敛
3. **DRC遗漏** - 小批量规则检查遗漏
4. **电源问题** - IR Drop过大, 芯片不稳定
5. **测试不足** - ATE向量不完善, 无法筛选坏片

### 最佳实践

✓ **预留20%时序余量** - 应对OCV、SI
✓ **多Corner验证** - 至少TT/SS/FF三个角
✓ **完善测试向量** - 覆盖所有功能点
✓ **早期封装评估** - 提前做封装样品
✓ **建立ECO流程** - 预案Metal Fix方案

`★ Insight ─────────────────────────────────────`
1. **流片前的最后一次检查**: 许多公司会进行"流片冻结期" - 流片前2周禁止任何代码修改, 只允许修复bug
2. **Mask成本是高昂的**: 在7nm节点, 一次流片的掩模成本可能高达$7.5M, 这是很多小公司的全部融资额
3. **文档同样重要**: 完整的文档包不仅帮助生产, 也利于未来维护和复用
