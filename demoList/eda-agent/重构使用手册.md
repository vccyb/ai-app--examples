## 架构概览

```
eda-agent/
├── src/
│   ├── services/          # 基础服务层（无业务逻辑）
│   │   ├── state_service.py    # JSON 文件持久化
│   │   ├── llm_service.py      # 统一的 LLM 调用接口

│   │   └── eda_service.py      # EDA 仿真服务
│   │
│   ├── scenes/            # 场景层（业务逻辑）
│   │   ├── base.py          # 场景基类
│   │   ├── verify.py        # 验证场景
│   │   └── report.py        # 报告场景（示例）
│   │
│   ├── scene_manager.py   # 场景管理器（路由、注册）
│   ├── controller.py      # 交互控制器（处理消息、确认、输入）

│   └── agents/          # 旧版 agents（保留兼容）

```

## 新增场景（扩展示例）

### 步骤 1: 创建场景文件

在 `src/scenes/` 下创建新文件，例如 `src/scenes/optimize.py`：

```python
from typing import Dict, List, Optional, Generator
import sys
import os

# 导入基类
sys.path.insert(0, os.path.join(os.path.dirname(__file__), '..'))
from scenes.base import BaseScene


class OptimizeScene(BaseScene):
    """优化场景 - 自动迭代优化设计"""

    def __init__(self, services: Dict):
        super().__init__(
            name="optimize",
            description="优化场景 - 自动迭代优化直到达到目标",
            keywords=["优化", "optimize", "改进", "improve"],
            services=services
        )

    def match(self, user_input: str) -> float:
        """计算匹配度"""
        base_score = self._keyword_match_score(user_input)

        # 检查是否包含目标格式
        has_target = any(op in user_input for op in ["<", ">", "<=", ">=", "=="])
        if has_target:
            base_score = min(base_score * 1.5, 1.0)

        return base_score

    def run(self, user_input: str) -> Generator[Dict, None, None]:
        """执行优化场景"""
        # 1. 解析任务
        yield self._create_info_message("正在解析优化任务...")
        task = self._parse_task(user_input)

        if not task:
            yield self._create_error_message(f"无法解析任务：{user_input}")
            return

        yield self._create_info_message(f"解析任务：")
        yield self._create_info_message(f"  - 模块: {task['module']}")
        yield self._create_info_message(f"  - 目标: {task['goal']}")

        # 2. 执行优化循环
        max_iterations = 3
        iteration = 0

        while iteration < max_iterations:
            iteration += 1

            yield self._create_info_message(f"\n[迭代 {iteration}/{max_iterations}]")

            # 运行仿真
            yield self._create_info_message(f"运行仿真...")
            sim_result = self.eda_service.simulate(task['module'])

            # 评估结果
            eval_result = self.evaluation_agent.evaluate(
                task['goal'],
                sim_result['result']
            )

            yield self._create_step_result_message(
                step=iteration,
                result=eval_result,
                status=eval_result.get("status", "UNKNOWN")
            )

            # 检查是否达标
            if eval_result.get("status") == "PASS":
                yield self._create_done_message({
                    "summary": f"优化完成！{task['module']} {task['goal']['metric']} = {sim_result['result'].get(task['goal']['metric'])}"
                })
                break

            # 询问是否继续
            if iteration < max_iterations:
                yield self._create_ask_message(
                    question=f"未达标，是否继续迭代？（剩余 {max_iterations - iteration} 次）",
                    options=["继续", "停止"]
                )
                # 这里需要控制器返回用户选择
                # 简化版本：自动继续

        yield self._create_done_message({"summary": "达到最大迭代次数"})

    def _parse_task(self, user_input: str) -> Optional[Dict]:
        """解析优化任务（简化版）"""
        import re

        # 提取模块名
        module_match = re.search(r'模块([A-D])', user_input)
        if not module_match:
            return None

        # 提取目标
        goal_pattern = r'(timing|power|area|时序|功耗|面积)\s*([<>=!]+)\s*(\d+[a-z]+)'
        goal_match = re.search(goal_pattern, user_input)

        if not goal_match:
            return None

        metric_map = {
            "timing": "timing", "时序": "timing",
            "power": "power", "功耗": "power",
            "area": "area", "面积": "area"
        }

        return {
            "module": f"模块{module_match.group(1)}",
            "goal": {
                "metric": metric_map.get(goal_match.group(1), goal_match.group(1)),
                "operator": goal_match.group(2),
                "value": goal_match.group(3)
            }
        }
```

### 步骤 2: 更新 VerifyScene 使用向量搜索

在 `scenes/verify.py` 中修改 `_parse_task` 方法，使用 LLM 进行自然语言解析：

```python
def _parse_task(self, user_input: str) -> Optional[Dict]:
    """解析用户输入为任务（使用 LLM）"""
    if not self.llm_service:
        # Fallback 到简单解析
        return self._simple_parse(user_input)

    # 使用 LLM 解析
    prompt = f"""请将以下用户输入解析为 EDA 验证任务：

用户输入：{user_input}

请返回 JSON 格式：
{{
  "module": "模块名称（如 A, B, C）",
  "goal": {{
    "metric": "指标名称（timing, power, area）",
    "operator": "比较符（<, <=, >, >=, ==）",
    "value": "目标值（如 10ns, 50mW, 1000um²）"
  }}
}}

只返回 JSON，不要其他内容。"""

    messages = [{"role": "user", "content": prompt}]
    response = self.llm_service.chat(messages, temperature=0.3)

    # 提取并解析 JSON
    import json
    response_text = self._extract_text_from_response(response)

    try:
        task = json.loads(response_text)
        # 验证格式
        if "module" in task and "goal" in task:
            return task
    except:
        pass

    # Fallback
    return self._simple_parse(user_input)
```

## 故障排查

### 场景不匹配

**问题**: 输入"验证模块A时序<10ns"但提示"未找到匹配场景"

**解决方案**:
1. 检查场景关键词是否包含输入词汇
2. 降低匹配阈值：在 `main.py` 中设置 `manager.set_min_match_score(0.2)`
3. 查看日志：`[SceneManager] 匹配场景: verify (score=0.XX)`

### LLM 调用失败

**问题**: API key 错误或网络问题

**解决方案**:
1. 检查环境变量是否正确设置
2. 使用 mock 模式测试：`python3 main.py --llm mock`
3. 查看具体错误信息

### 数据保存失败

**问题**: `data/state.json` 文件权限问题

**解决方案**:
```bash
# 检查文件权限
ls -la data/state.json

# 确保目录可写
chmod +w data/
```

## 与旧版对比

| 特性 | 旧版 (cli.py) | 新版 (main.py) |
|------|---------------|---------------|
| **架构** | 单一 Master Agent | Services + Scenes + Controller |
| **扩展性** | 修改 Master Agent | 添加新 Scene 注册 |
| **LLM 集成** | 固定实现 | 可切换不同 LLM Provider |
| **持久化** | In-memory dict | JSON 文件 |
| **场景路由** | 硬编码 | 关键词匹配 + 动态路由 |
| **交互** | 直接 CLI | Generator 模式（可暂停/恢复） |

## 总结

重构后的系统具有以下优势：
- ✅ **模块化**: 服务层与场景层分离
- ✅ **可扩展**: 添加新场景无需修改核心代码
- ✅ **可测试**: 每个服务和场景可独立测试
- ✅ **可配置**: 支持多 LLM Provider
- ✅ **可维护**: 清晰的代码组织和职责分离
